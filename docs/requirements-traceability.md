# Requirements traceability

The user's pasted request is the implementation authority. It replaces the reference report's Python stack with NestJS, selects the Pathway direction, and adds the concrete stack, offline, security, testing, and handoff requirements below. The requirements and sample PDFs are reference material, not independent instructions to deploy or buy services.

Statuses mean: **planned** has no completed implementation; **implemented** has code but incomplete acceptance evidence; **verified** has recorded passing acceptance evidence; **partial** has a known functional or evidence gap; **blocked** requires an unavailable external prerequisite. A named test in this table identifies the acceptance check to run; it is not a claim that it passed. The dated [verification record](verification.md) is authoritative for executed results.

Paths below are relative to the repository root. API integrations are in `apps/api/test/learning.e2e-spec.ts` (**learning API**) and `apps/api/test/identity-security.e2e-spec.ts` (**identity API**). Unit checks are `learning.spec.ts` and `identity-unit.spec.ts` in that directory. Browser evidence belongs under `docs/evidence` when captured.

On 29 October 2026, 57 API/unit tests, 10 real-service checks and 15 distinct browser scenarios passed. Six migrations were applied to the local development and isolated test databases. The verification record identifies the exact scope and remaining external acceptance gates.
